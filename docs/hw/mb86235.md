## 1. Architecture

### 1.1 Memories and address spaces
| Space | Size | Notes | Conf |
|---|---|---|---|
| Program | 4096 x 64-bit words, 12-bit PC | RAM, filled by the i960 upload. Word-addressed. | C2 [CORE][M2] |
| A data RAM (internal) | 1024 x 32-bit, addr 0x000-0x3FF | Reached over the "A bus". | C1 [CORE] |
| B data RAM (internal) | 1024 x 32-bit, addr 0x000-0x3FF | Reached over the "B bus". It also holds the data stack (SP). | C1 [CORE] |
| External | 24-bit word address, 32-bit data | Reached via EB/EO, or via A-bus addresses at or above 0x400 (see 3.3). | C2 [CORE][OPS][M2] |

All data words are 32-bit. Address registers are 14 bits wide, so the A-bus range is 0-0x3FFF. B-bus addresses are masked to 10 bits.

### 1.2 Registers
| Reg | Count/width | Purpose | Conf |
|---|---|---|---|
| AA0-7, AB0-7 | 16 x 32 | ALU input registers ("A side", AA/AB banks). ALU and MUL outputs can also be written here. | C2 |
| MA0-7, MB0-7 | 16 x 32 | Multiplier input registers. ALU and MUL outputs can also be written here. | C2 |
| AR0-7 | 8 x 14-bit | Address registers. Writes are masked to 0x3FFF; post-inc/dec wrap at 14 bits. | C1 [OPS] |
| PR | 24 x 32 | Register queue. A write goes to `PR[PWP]` and then PWP++. ALU/MUL reads take `PR[PRP]` with an optional PRP++, --, or reset to 0. Both pointers wrap modulo 24. | C2 [OPS][DRC] |
| PRP, PWP | 5-bit | PR read and write pointers. Writing a value of 24 or more is fatal in MAME. | C1 |
| EB | 24-bit | External base. It is split as EBU = EB>>14 (high part) and EBL = EB & 0x3FFF. | C1 |
| EO | 24-bit? | External offset. Each external transfer adds a signed 6-bit displacement to it. | C1 |
| SP | 10-bit | Data-stack pointer into B RAM. PUSH pre-decrements; POP post-increments. | C1 |
| ST | 32 | Status/flags (table 1.3). | C2 |
| MOD | 16 | Mode register; fields set by SETM (see 2.8). | C1 |
| LPC | ? | Loop counter (SETL/DBLP). The disassembler names it "LRPC". | C1 |
| RPC | ? | Repeat counter (REP). Not in the transfer register map. | C1 |
| PC stack | 4 entries | Holds return addresses for DCALL/DRET. MAME wraps the pointer modulo 4 with no fault. | C1 [OPS]; G for real overflow behaviour |
| PDR, DDR | 32 | Probably port/data-direction registers. On Model 2 these drive error-LED flags (TODO in [CORE]). | G |
| ICDTR0-7 | ? | Only appear as MOV4 targets. Not implemented anywhere. | G |

**Transfer register code (6-bit; a 7-bit field adds memory selection, see 2.4).** This table is consistent between [DIS] and [OPS], so C2.

| code | 0-7 | 8-F | 10 | 11 | 12 | 13 | 14 | 15 | 16 | 17 | 18-1F | 20-27 | 28-2F | 30 | 31 | 32 | 33 | 34 | 35 | 36 | 37 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| reg | MA0-7 | AA0-7 | EB | EBU | EBL | EO | SP | ST | MOD | LPC | AR0-7 | MB0-7 | AB0-7 | PR | FI | FO0 | FO1 | PDR | DDR | PRP | PWP |

FI can only be read; FO0 and FO1 can only be written. Codes 0x38-0x3F are undefined.

[OPS] has a bug: writing EBL shifts the value into the high bits. Implement EBL as "replace the low 14 bits". **G**

### 1.3 Status register (ST) bits [OPS]
| bit | 0 | 1 | 2 | 3 | 4 | 8 | 9 | 10 | 11 | 14 | 15 | 16 | 17 | 18 | 19 | 20 | 24 | 25 | 26 | 27 | 28-30 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| flag | AD | AU | AV | AZ | AN | ZC | IL | NR | ZD | RP | LP | MD | MU | MV | MZ | MN | OFF | OFE | IFF | IFE | F0-F2 |

What the flags mean:
- **A-flags** (AN/AZ/AV/AU/AD): ALU negative, zero, overflow, underflow, denormal(?).
- **M-flags**: the same set for the multiplier.
- **ZC**: set when a Z-suffixed op clamped a negative result to zero.
- **IL**: illegal input to FLOG.
- **NR**: non-positive input to FRSQ.
- **ZD**: divide by zero in FRCP.
- **RP / LP**: repeat active / loop active.
- **IFF/IFE/OFF/OFE**: FIFO in full/empty, out full/empty.
- **F0-F2**: user or external flags.

Confidence for the bit positions is C1, and the meanings are partly G. MAME never sets AD/AV/AU for most ops; [DRC] has TODOs for AV/AU/AD/MV/MU/MD.

### 1.4 Number formats
- Float: 32-bit IEEE-754 single precision. MAME reinterprets the bits as a host `float`, and FEA/FES operate on bits 30..23 as the exponent. **C2 within MAME, G with respect to real silicon.** Rounding mode, denormal handling, and NaN/Inf behaviour on the real chip are unknown. The MV/MU/MD flag names suggest the chip detects overflow, underflow, and denormal cases.
- Integer: 32-bit two's complement. Integer MUL keeps the low 32 bits in MAME. **G**: the width of the real multiplier is unknown.
- reModel (`mb86235::float`): the host's IEEE single arithmetic, rounded to nearest with denormals, and a NaN result defined as the first NaN operand (in the instruction's order) quieted, else `0xFFC00000`, so every build gives the same bits. The chip's NaN rules are unknown. The native 2C geometrizer (`geometrizer-2c.md`) computes with the same functions.

### 1.5 Clock and throughput
- MAME runs the 2C TGPx4 at 20 MHz [M2]. [NAMU] claims 40 MHz. **Unresolved**; the chip may use an internal multiplier.
- MAME executes 1 instruction per cycle. Taken branches cost +1 cycle, DBBC/DBBS +2, and relative targets +1. **G**
- [M2]'s file header says "2x TGPx4" for Model 2C, and [NAMU] says two chips. However, MAME's model2c config instantiates only one. **G**: check the PCB.

## 2. Instruction encoding (64-bit word)

All bit positions are numbered with 63 = MSB. Fields are given as hi..lo.

### 2.1 Top level: bits 63..61 [DIS][OPS], C2
| 63..61 | Format | Slots |
|---|---|---|
| 000 | **F0** | ALU **and** MUL + double transfer, type 1 (MVD1) |
| 001 | **F1** | ALU **and** MUL + single transfer, type 1 (MOV1) |
| 010 | **F2** | ALU **and** MUL + control |
| 011 | n/a | Illegal (MAME aborts) |
| 100 | **F4** | ALU **or** MUL + double transfer, type 2 (MVD2/MOVI) |
| 101 | **F5** | ALU **or** MUL + single transfer, type 2 (MOV2/MOV4) |
| 110 | **F6** | ALU **or** MUL + control |
| 111 | **F7** | MOV3: 32-bit immediate transfer only (no ALU or MUL) |

Bit 63 chooses between the two forms. With bit 63 = 0, the word has an ALU slot plus a MUL slot in bits 60..27, and the transfer or control part uses bits 26..0. With bit 63 = 1, there is one arithmetic op in bits 60..41, and the transfer part can use bits 40..0. Control in F6 still uses only 26..0.

### 2.2 Arithmetic slots
**F0/F1/F2 (both ALU and MUL).** C2:
| field | bits | width |
|---|---|---|
| ALU op | 60..56 | 5 |
| ALU in1 (AI1) | 55..52 | 4 |
| ALU in2 (AI2) / imm5 | 51..47 | 5 |
| ALU out (AO) | 46..42 | 5 |
| MUL type (0 = MUL int, 1 = FMUL) | 41 | 1 |
| MUL in1 (MI1) | 40..37 | 4 |
| MUL in2 (MI2) | 36..32 | 5 |
| MUL out (MO) | 31..27 | 5 |

**F4/F5/F6 (one op).** Bits 60..42 have the same layout as the ALU slot above. Bit 41 = 1 means ALU, using the bits as an ALU op. Bit 41 = 0 means MUL: in that case bit 56 = 1 selects FMUL and 0 selects integer MUL, and the input/output fields are reinterpreted as MI1/MI2/MO. C2.

[DIS] has a quirk here: in F0-F2 it always prints the ALU op, and it uses bit 41 both as the MUL type and as an "ALU present" flag. Those two uses cannot both be right, so read bit 41 as MUL type only in the two-op formats.

**Operand codes.** Confidence is C2 except where noted.
- AI1 (4b): 0-7 = AA0-7, 8-F = AB0-7.
- MI1 (4b): 0-7 = MA0-7, 8-F = MB0-7.
- AI2 / MI2 (5b):
  - 0x00-0x0F: same as AI1 / MI1.
  - 0x10 PR, 0x11 PR++ (then PRP++), 0x12 PR-- (then PRP--), 0x13 PR#0 (read, then PRP=0).
  - 0x14-0x17: undefined.
  - 0x18-0x1F constants:
    - float ops: -1.0, 0.0, 0.5, 1.0, 1.5, 2.0, 3.0, 5.0.
    - integer ALU ops: 0x18 = 0, 0x19 = 1, 0x1A = -1; 0x1B-1F undefined. [DIS] prints float constants for integer MUL; [OPS] uses the integer constants. **G**
- AO / MO (5b): 0-7 MA, 8-F MB, 10-17 AA, 18-1F AB.
- Float vs integer for AI2: ALU ops with bit 4 = 0 are float [OPS].

### 2.3 ALU opcodes (5-bit) [DIS][OPS], C2 for names, C1 for semantics
Semantics follow MAME. **Operand order: subtract and compare compute `in2 - in1`** [OPS] (C1, verify with real code).

| op | mnem | operation | op | mnem | operation |
|---|---|---|---|---|---|
| 00 | FADD i1,i2,o | o = i1+i2 | 10 | ADD | int i1+i2 |
| 01 | FADDZ | as FADD, then clamp a negative result to 0 and set ZC | 11 | ADDZ | int, clamp to 0 (ZC) |
| 02 | FSUB | o = i2-i1 | 12 | SUB | int i2-i1 |
| 03 | FSUBZ | i2-i1, clamped (ZC) | 13 | SUBZ | int, clamped |
| 04 | FCMP i1,i2 | flags only, from i2-i1 | 14 | CMP | int flags from i2-i1 |
| 05 | FABS i1,o | \|i1\| | 15 | ABS | clear bit 31 |
| 06 | FABC i1,i2 | flags only, from \|i2\|-\|i1\| | 16 | ATR i1,o | o = i1 (transfer, no flags) |
| 07 | NOP | nothing | 17 | ATRZ | o = i1, or 0 if negative (ZC) |
| 08 | FEA i1,#imm5,o | exponent += imm5 | 18 | AND | i1 & i2 |
| 09 | FES i1,#imm5,o | exponent -= imm5 | 19 | OR | i1 \| i2 |
| 0A | FRCP i1,o | 1/x (ZD if x == 0) | 1A | XOR | i1 ^ i2 |
| 0B | FRSQ i1,o | 1/sqrt(x) (NR if x <= 0) | 1B | NOT i1,o | ~i1 |
| 0C | FLOG i1,o | log2(x) (IL if x <= 0) | 1C | LSR i1,#imm5,o | logical shift right |
| 0D | CIF i1,o | int to float | 1D | LSL | shift left |
| 0E | CFI i1,o | float to int (truncate in MAME) | 1E | ASR | arithmetic shift right |
| 0F | CFIB i1,o | float to unsigned byte, saturating 0..255 (AU/AV) | 1F | ASL | arithmetic shift left |

Flags: most ops update AN/AZ, and ATR does not. MAME's implementations of FEA/FES and FLOG look wrong:
- FEA/FES keep only the exponent bits.
- FLOG computes ln(x) divided by log10(2).

Implement both from first principles, **G**. The rounding of CFI and the exact accuracy of FRCP/FRSQ (whether they are table-based approximations) are unknown.

### 2.4 Memory operand addressing
In MOV-type fields, a 7-bit register/memory code is used:
- bit 6 = 0: the code is a register from table 1.2.
- bit 6 = 1: the operand is memory, with bit 5 = 0 for A bus and 1 for B bus, and bits 2..0 = ARx. Code **0x58 is the immediate form** (source only). C2.

Each instruction has a 4-bit addressing-mode field (MD) plus ARy and a displacement. Address = value before any post-modify. C2 for names, C1 for semantics.

| MD | form | address; side effect |
|---|---|---|
| 0 | @ARx | ARx |
| 1 | @ARx++ | ARx; ARx += 1 |
| 2 | @ARx-- | ARx; ARx -= 1 |
| 3 | @ARx++disp | ARx; ARx += disp |
| 4 | @ARx+ARy | ARx+ARy |
| 5 | @ARx+ARy++ | ARx+ARy; ARy += 1 |
| 6 | @ARx+ARy-- | ARx+ARy; ARy -= 1 |
| 7 | @ARx+ARy++disp | ARx+ARy; ARy += disp |
| 8 | @ARx+ARyU | A bus: ARx + (ARy>>7). B bus: ARx + (ARy & 0x7F). |
| 9 | @ARx+ARyL | the opposite split from mode 8 |
| A | @ARx+disp | ARx+disp |
| B | @ARx+ARy+disp | sum of all three |
| C | disp | absolute. **[OPS] does not implement this mode (fatal); [DIS] shows it.** G |
| D | @ARx+[ARy++] | ARx + (ARy masked to a circular-buffer size from MOD.CBSA or CBSB); ARy++ |
| E | @ARx+[ARy--] | same, with ARy-- |
| F | @ARx+[ARy++disp] | same, with ARy += disp |

The meaning of the "[ ]" modes 13-15 (circular versus bit-reversed) is **G**. MAME computes `ARy & (0x1FF >> (7 - CBS))`.

Post-modify results are masked to 14 bits. MD/ARy/disp field positions by format:

| fmt | MD | ARy | disp |
|---|---|---|---|
| F1 | 3..0 | 6..4 | 11..7 (5b) |
| F5 | 3..0 | 6..4 | 20..7 (14b) |
| F7 | 3..0 | 6..4 | 18..7 (12b) |

### 2.5 Single transfer type 1: MOV1 (F1, bits 26..0)
| field | bits |
|---|---|
| TRM (1 = external transfer) | 26 |
| DIR (only when TRM = 1: 1 = ext to int, 0 = int to ext) | 25 |
| SR (7b code; when TRM = 1, bits 24..19 are a signed 6-bit EO displacement) | 25..19 |
| DR (7b code; the internal side when TRM = 1) | 18..12 |
| disp5 / ARy / MD | 11..7 / 6..4 / 3..0 |

If SR = 0x58, the instruction loads `#imm12` from bits 11..0 into DR. An external transfer accesses the word at EB+EO, then adds the signed displacement to EO. C2.

### 2.6 Single transfer type 2: MOV2/MOV4 (F5, bits 40..0)
| field | bits |
|---|---|
| OP (0 = MOV2, 2 = MOV4 to ICDTRn) | 40..39 |
| TRM | 38 |
| DIR | 37 |
| SR (signed 6b EO displacement in 36..31 when TRM = 1) | 37..31 |
| DR | 30..24 |
| disp14 / ARy / MD | 20..7 / 6..4 / 3..0 |

If SR = 0x58, the instruction loads `#imm24` from bits 23..0. [OPS] ignores OP, so it would execute MOV4 as MOV2. **G**

### 2.7 Double transfers
**MVD1 (F0, bits 26..0).** One A-bus and one B-bus move happen in parallel. MD is shared and there is no displacement: modes 3/7/A/B/C/F are invalid.

| SD (26..25) | layout |
|---|---|
| 0 reg to reg | A: src 24..20, dst 19..15. B: src 14..10, dst 9..5 (B codes OR 0x20, so MB/AB) |
| 1 reg to mem | A reg 24..20, A ARx 19..17, ARy 16..14. B reg 13..10 (OR 0x20), B ARx 9..7, ARy 6..4. MD 3..0 |
| 2 mem to reg | same fields as SD 1, opposite direction |
| 3 | illegal |

[DIS] layout. [OPS] gets SD = 0 wrong: it reads and writes the same field. **G**

MD 8/9 in MVD1 give the A side and B side opposite U/L halves of ARy.

**MVD2 (F4, bits 40..0).** The A side uses bits 39..20 and the B side uses bits 19..0.

| part | fields |
|---|---|
| A side | SDA 39..38. Reg/src 37..33, dst 32..28. EA: ARx 32..30, ARy 29..27, disp3 26..24, MD 23..20 |
| B side | SDB 19..18. Reg/src 17..13, dst 12..8. EA: ARx 12..10, ARy 9..7, disp3 6..4, MD 3..0 |

When the side is mem-to-reg (SD = 2), [DIS] takes the register from bits 37..33 (A) or 17..13 (B). [OPS] takes it from the "dst" field, which overlaps the EA. **Trust [DIS]. G**

**MOVI (F4 with SDA = 3).** Reads `B(ea)` using the B-side EA fields and writes it to instruction memory at `I(@ARx++)`, with ARx in bits 32..30. This lets a program write its own program memory. It is not executed by [OPS]. **G**

### 2.8 Control (F2/F6, bits 26..0)
| field | bits |
|---|---|
| COP | 26..22 |
| EF1 | 21..16 |
| EF2 | 15..0 |

C2 for the opcode numbers.

| COP | mnem | semantics (per [OPS]) |
|---|---|---|
| 00 | NOP | nothing |
| 01 | REP n / REP ARx | Sets RPC and the RP flag. The **next** instruction runs n times. |
| 02 | SETL n / SETL ARx | Sets LPC and the LP flag. |
| 03 | CLRFI/CLRFO/CLRF | Clears FIFOs: EF1 bit 0 = input, bit 1 = output. |
| 04 | PUSH reg | SP--, then B[SP] = reg. The register is a 6-bit code in EF2 bits 11..6. |
| 05 | POP reg | reg = B[SP], then SP++. Applied **after** the parallel ALU op. |
| 08 | SETM #imm16 | MOD = EF2 |
| 09 | SETM CBSA | MOD bits 14..12 |
| 0A | SETM CBSB | MOD bits 11..9 ([OPS] mask) or 10..8 ([DIS] print and EA use). **G** |
| 0B | SETM RF | MOD bit 7 |
| 0C | SETM RDY | MOD bit 4 |
| 0D | SETM WAIT | MOD bits 2..0. Meaning unknown (wait states?). |
| 10 | DBcc tgt | delayed branch if condition true |
| 11 | DBNcc tgt | delayed branch if condition false |
| 12 | DJMP tgt | delayed jump |
| 13 | DBLP rel12 | If LP is set, branch. Then LPC--, and when LPC reaches 1, clear LP. The body runs LPC times. |
| 14 | DBBC ARx:bit, rel12 | branch if bit (19..16) of ARx (15..13) is clear |
| 15 | DBBS | same, branch if set |
| 18 | DCcc | delayed conditional call |
| 19 | DCNcc | delayed call if condition false |
| 1A | DCALL | delayed call; pushes the address after the delay slot |
| 1B | DRET | delayed return (pops the PC stack) |
| others | n/a | illegal/unknown |

**REP/SETL operand source.**
- [DIS]: EF1 = 0 means immediate, from EF2. Otherwise the operand is ARx, with x in EF2 bits 14..12.
- [OPS]: EF1 = 0x3F means ARx, with x in EF2 bits **15..13**.

The two disagree. **G**: resolve this from real code.

**Condition codes (EF1, 6 bits).** C2.

| cc | 00 | 01 | 02 | 03 | 04 | 05 | 06 | 07 | 08 | 09 | 0A | 0B | 0C | 0D | 10 | 11 | 12 | 14 | 15 | 16 | 17 | 18 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| flag | MN | MZ | MV | MU | ZD | NR | IL | ZC | AN | AZ | AV | AU | MD | AD | F0 | F1 | F2 | IFF | IFE | OFF | OFE | IF |

Codes 0E, 0F, 13, and 19-3F are undefined. IF is the input FIFO's 33rd bit; MAME always returns false for it.

**Branch target for DBcc/DBNcc/DJMP/DCcc/DCNcc/DCALL (EF2).** C2 for the layout; [DRC] differs.
- Bits 15..13 = source type.
- Bit 12 = relative: add the PC.
- The register forms use a 6-bit register code in bits 11..6, or equivalently bank bit 11 plus index bits 8..6.

| type | target |
|---|---|
| 0 | imm12 (bits 11..0) |
| 1 | ARx |
| 2 | AAx/ABx |
| 3 | MAx/MBx |
| 4 | A-RAM[imm10] |
| 5 | B-RAM[imm10] |
| 6 | A-RAM[ARx] |
| 7 | B-RAM[ARx] |

The result is masked to 12 bits. Computed jumps (types 1-7) mean the disassembler cannot always resolve targets statically.

**Relative base: an off-by-one conflict, G.**
- [DIS] and [DRC] compute the target as `addr_of_branch + sext12(disp)`.
- [OPS] computes `addr_of_branch + 1 + disp12 (mod 4096)`.

[OPS] is the code that runs games in MAME, but the 2C games are not fully working. Resolve this empirically: DBLP loop targets in the Top Skater image should land on plausible loop heads.

## 3. FIFOs and external memory (Model 2C)

### 3.1 Program access
- **Read input FIFO**: use FI (code 0x31) as the source of any transfer. **C2**
- **Write output FIFO**: write FO0 (code 0x32). FO1 (0x33) writes the same FIFO but tags a 33rd bit, which Model 2 does not use. **C1**
- **Poll**: conditions IFE/IFF/OFE/OFF, for example `DBIFE` to loop while the input FIFO is empty. **C2**
- **Clear**: CLRFI/CLRFO. **C2**

### 3.2 Blocking behaviour [OPS][M2]
Reading FI while the input FIFO is empty **stalls** the processor. In MAME, the whole instruction is suppressed and retried: the ALU op is skipped, AR post-modifies are skipped, and the PC is held until data arrives. Writing FO0 while the output FIFO is full halts the TGPx4 until the i960 drains it. For the HLE, treat FI reads as blocking and FO writes as blocking. **C1** for the mechanism. Stalls inside REP are an unhandled "check me" case in MAME (**G**).

MAME uses FIFO depth 8 for 2C (**G**; the real depth is unknown). When the i960 reads an empty output FIFO, the i960 stalls.

### 3.3 External address space (24-bit word addresses) [M2], C1
| TGPx4 ext address (words) | Contents |
|---|---|
| 0x400000-0x407FFF | "bufferram", 32K x 32 = 128 KB, shared with the i960 side. Mirrored over 0x400000-0x7FFFFF. |
| 0x800000-0x9FFFFF | "copro_data" ROM, 2M words = 8 MB window. Top Skater fills 4 MB: mpr-19743 and mpr-19744, word-interleaved. MAME's comment calls this region "TGPx4 program", but it is data; the program comes from the i960 upload. |

There are two access paths:
- EB+EO transfers, the `E(@EB+EO++d6)` forms.
- Any A-bus address from 0x400 up, which reaches external memory at `(EB & 0xFFC000) + (addr & 0x3FFF)`. This makes EBU a 16K-word bank register. [OPS], **C1**

### 3.4 i960-side interface (2C-CRX) [M2], C1
| i960 address | Function |
|---|---|
| 0x00980000 | copro control. Bit 31 going 0→1 starts an upload: the word count resets and the copro halts. Bit 31 going 1→0 boots the copro: the halt is released. |
| 0x00884000-0x00887FFF | Write: during upload, program words (pairs of dwords, **low dword first, then high**); otherwise, push to the input FIFO. Read: pop the output FIFO. |
| 0x00880000-0x00883FFF | "Function port": write pushes `(data & 0x800FFFFF) \| (fn << 23)`, where fn = (dword offset >> 2) & 0xFF. |
| 0x00980014 | copro status: returns all-ones while the upload count is 0, otherwise 0. |

A full upload is 4096 words, or 8192 dword writes. MAME's 2C boot does **not** reset the PC; the PC is 0 only from machine reset. Real hardware likely resets the PC on boot. **G**

## 4. Execution order, pipeline, delay slots

1. **Delayed control flow, one delay slot.** C2. Every branch, call, and return (all the D-mnemonics) executes exactly one following instruction before the target. DCALL pushes the branch address + 2. Behaviour with a branch in a delay slot is undefined: MAME TODO "illegal delay slots unsupported".
2. **Conditions use flags from before the current word.** C2. In both [OPS] and [DRC], the condition is evaluated before the parallel ALU/MUL op in the same word updates the flags. [DRC]'s TODO "check jump condition before parallel ALU/MUL (flags!)" shows this was a deliberate guess. Register-sourced branch targets are also read before the ALU writes.
3. **Within one word, the effective semantics is read-all, then write-all.** C1 [OPS]. The order is:
   1. The transfer source is read (memory, register, or FI pop).
   2. The ALU and MUL sources are read.
   3. The ALU result is written, then the MUL result.
   4. The transfer destination is written. A transfer to the same register as an ALU output therefore wins.
   5. POP is written last.

   [DRC] models the same rule with "register clash" temporaries. PR++/PR-- side effects happen in read order: ALU, then MUL.
4. **REP n** re-executes the next instruction n times, holding the PC. AR post-modifies and PR side effects apply on each repetition. The behaviour for n = 0 or 1 is unknown. C1
5. **Result latency.** MAME assumes results are visible to the next instruction. Real FRCP/FRSQ/FMUL latencies are unknown (**G**). Watch the uploaded code for NOP padding after these ops as a hint.
6. **Self-modifying code.** MOVI can write program RAM, so a static recompiler must at least detect MOVI.

## 5. Open questions (ranked by impact on reModel)

1. **Relative branch base**: is it the branch address or the branch address + 1? Settle it by disassembling the Top Skater program with both options and checking DBLP/DBcc targets.
2. **REP/SETL operand encoding**: which EF1 value selects ARx, and whether the AR index is in bits 14..12 or 15..13.
3. **MVD1 SD = 0 and MVD2 mem-to-reg register fields**: [DIS] and [OPS] disagree.
4. **Float details**: FRCP/FRSQ/FLOG precision (table-based?), CFI rounding, denormals, and flag semantics (AV/AU/AD/MV/MU/MD). Also the true semantics of FEA/FES/FLOG.
5. **Operand order** of SUB/FSUB/CMP (MAME: in2 - in1).
6. Addressing mode **0xC** (absolute) and the meaning of the "[ARy]" modes and the CBSA/CBSB fields.
7. Never implemented: **MOV4/ICDTR**, **MOVI**, PDR/DDR, the MOD RF/RDY/WAIT bits, and the F0-F2 flag sources.
8. Clock (20 vs 40 MHz), FIFO depth, and whether 2C-CRX has one or two TGPx4 chips.
9. Whether PC-stack overflow and underflow (4 entries) trap or wrap; MAME has unused `pcs_overflow` hooks.
10. Data RAM sizes: is 1K + 1K internal real? The 14-bit AR width suggests the A-bus external window was intended.
