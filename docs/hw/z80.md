# Zilog Z80 core (`crates/z80`)

A generic Z80 interpreter for the Model 2 boards that carry one. The first
user is the DSB1 music board in `stcc` (Sega Touring Car
Championship), where a Z80 runs `epr-19275.2s` and feeds the MPEG decoder
(`docs/hw/dsb1.md`). The crate knows nothing about any
board.

Written clean-room from Zilog's Z80 CPU User Manual and the publicly known
undocumented behaviour; no emulator code was read or copied. Checked against
Frank Cringle's instruction exercisers, zexdoc and zexall (`make z80-test`).

## Interface

A board implements `z80::Bus`, the same shape as `m68k::Bus`:

```rust
pub trait Bus {
    fn read(&mut self, addr: u16) -> u8;
    fn write(&mut self, addr: u16, v: u8);
    fn fetch(&mut self, addr: u16) -> u8 { self.read(addr) } // M1 opcode fetches
    fn input(&mut self, port: u16) -> u8;                    // IN, full 16-bit port
    fn output(&mut self, port: u16, v: u8);                  // OUT, full 16-bit port
    fn int_ack(&mut self) -> u8 { 0xff }                     // IM 0 opcode / IM 2 vector byte
    fn reti(&mut self) {}                                    // RETI seen
}
```

- `Cpu::step(&mut bus)` runs one instruction (a prefixed one counts as one,
  so no interrupt is taken between a prefix and its opcode), accepts one
  interrupt, or idles one HALT cycle, and returns the T-states used.
  `Cpu::run(&mut bus, budget)` steps until the budget is spent.
- `set_int(bool)` drives the level-sensitive INT line; `set_nmi(bool)` the
  NMI line, taken on its rising edge.
- Port addresses carry the high byte the chip puts on A8-A15: A for
  `IN A,(n)` / `OUT (n),A`, B for the `(C)` forms and the block I/O
  instructions (B after its decrement for OUTI/OTIR and friends).
- Save states: `state::State` through `fields!`, all registers, the
  alternate set, IFFs, mode, MEMPTR, HALT, the EI delay and the line states.

## What's modelled

- Every documented instruction, all prefixes (CB, DD, ED, FD, DDCB, FDCB).
- Undocumented: flag bits 3 and 5 everywhere, MEMPTR (WZ) as BIT n,(HL)
  shows it, IXH/IXL/IYH/IYL, SLL, DDCB/FDCB results copied to a register,
  `IN (C)` / `OUT (C),0`, the ED mirrors of NEG, RETN and IM, unused ED
  opcodes as 8 T-state NOPs, DD/FD before a non-index instruction as a
  4 T-state prefix, and the block I/O flags.
- R: the low seven bits count M1 cycles (one per opcode or prefix fetch, and
  one per interrupt acknowledge); bit 7 changes only through `LD R,A`.
- Interrupts: IFF1/IFF2, modes 0, 1 and 2, NMI (IFF1 cleared, IFF2 kept for
  RETN), HALT (resumes after the HALT), and no interrupt straight after EI.
- Timing: the manual's T-state counts, including the taken/not-taken and
  repeat/last-iteration cases. Interrupt acceptance: NMI 11, IM 1 and an RST
  in IM 0 13, IM 2 19.

## Not modelled, or unconfirmed

- Bus accesses aren't placed within the instruction's T-states: all of an
  instruction's reads and writes happen together.
- IM 0 with anything but an RST: the opcode comes from `int_ack`, but any
  operand bytes are read from memory at PC, not from the device.
- The X/Y flags a repeating block instruction leaves when interrupted
  mid-repeat (found in 2018 on real chips; no exerciser checks them).
- SCF/CCF take X/Y from A alone (the NMOS/CMOS difference that depends on
  the previous instruction isn't modelled; zexall passes with this).
- The NMOS quirk where `LD A,I` / `LD A,R` read P/V as 0 if an interrupt is
  accepted right after them.
- AF and SP are set to 0xffff on reset, as commonly found on NMOS parts; the
  manual leaves them undefined.
- No disassembler yet.

## Testing

`cargo test -p remodel-z80` runs the unit tests (DAA, block instructions,
16-bit arithmetic flags, BIT undocumented flags, index halves, interrupt
modes, EI delay, HALT, NMI, R, ports, timing, save states).

`make z80-test` runs zexdoc and zexall from `out/z80-tests/` (`Z80_TESTS=`
to change) through a minimal CP/M stub (BDOS functions 2 and 9), in release.
The exercisers are freely redistributable but are not committed; without
them the target prints where to fetch them (the `.com` files from the
z80emu repository's `testfiles/` directory, for example).
