# MB86234 (the Model 2A TGP): what is known of its programs

The Model 2A's geometry processor is a Fujitsu MB86234 (the "TGP" of the
original Model 2 and 2A boards; the 2C's is an MB86235, `mb86235.md`). No
public manual for it has been found, and nothing here is taken from any
emulator. **Its instruction set is not known**: this file records what the
`srallyc` program image shows by its shape, and says for each point how it
is known. There are no mnemonics here and the tools (`remodel tgp-disasm`)
decode nothing.

Source of everything below: the 1,665-word program `srallyc` uploads
(`out/srallyc/tgp.bin`, written by `make run GAME=srallyc`; it is also
in the game's program ROM at `0x5AE94`), and the calls the game makes to it
(`model2a.md` §4).

## Program format

- **Fixed 32-bit words** (*confirmed*): the game uploads the program with
  one 32-bit store per word to the TGP's port (`model2a.md` §4), 1,665 of
  them. (The 2C's MB86235 takes 64-bit words.)
- **The top byte looks like an opcode field** (*hypothesis*): the 1,665
  words use 30 distinct top bytes, and four of them (`1C`, `BF`, `1D`,
  `01`) are 80% of the words:

  | Top byte | Words | | Top byte | Words |
  |---|---|---|---|---|
  | `1C` | 740 | | `3C` | 25 |
  | `BF` | 285 | | `BE` | 22 |
  | `1D` | 177 | | `63` | 18 |
  | `01` | 127 | | `02` | 17 |
  | `1F` | 52 | | `5A` | 16 |
  | `00` | 46 | | `39`, `5B` | 14 each |
  | `3B` | 30 | | `51` | 12 |
  | `1E` | 26 | | 14 more values | 1-7 each |

  `remodel tgp-disasm` prints the table for any image.
- **Header: six jump-like words** (*confirmed* as words of this form; that
  they are jumps is a guess): `BF600010 BF600006 BF600006 BF600006
  BF60000A BF600006`. Their low 16 bits (`0x10`, `6`, `6`, `6`, `0xA`, `6`)
  are word addresses inside the image, and `6` is the first word after the
  header, so the header reads as a vector table (reset and interrupt
  vectors?) whose entries mostly point at the start of the code. The same
  six words begin the programs of `daytona`, `vcop`, `desert`, `manxtt`,
  `motoraid`, `dynamcop` and `vf2` (the scoping pass that found them; only
  `srallyc`'s is re-read here), so the vector layout belongs to the chip.
- **Dispatch table at words 0xAE-0x12F: 130 entries** (*confirmed*): 128
  of the words are `BF60xxxx` and two (slots 0 and 129) `BF6A0000`, whose
  low 16 bits are 0. Every `xxxx` is an address inside the image (the
  highest is `0x67B`). It is indexed by **function number**
  (*confirmed*): each of the 31 functions the game calls
  (`model2a.md` §4, 2 to `0x5F`) has a slot whose target is code (the load
  check's function 8, which the stand-in answers itself, points at
  `0x16D`). 81 distinct targets serve the 128 live slots.
- **Functions share their tails** (*confirmed*): function 3's entry
  (`0x13F`) is the third word of function 2's code (`0x13D`), whose first
  words are `1C10F800 BF6A0000 1C1DC47C BF6A0000...`; function 5 (`0x168`)
  enters function 4's code (`0x15E`) at its eleventh word. A function's
  extent therefore isn't "up to the next entry"; the listing marks entries
  only.
- Of the 285 `BF` words, 130 are the table's. `BF6A0000` is the
  commonest in the code (84 times, often followed by an ordinary word); a
  `BF` word with `6A` and a zero address looks like a return (a guess, of
  the same form as the null dispatch slots). `BF64xxxx` (45 words) and
  `BF60xxxx` (21) in the code carry addresses inside the image and look
  like jumps or calls of two kinds; 20 `BF` words end the image (words
  0x66D-0x680).
- `1C1C3200`, `1C1C3201`, ... `1C1C320F` appear in order in words 0x14-0x37
  with other words between (`3B...`, `3C...`, `5A...`): they count up in
  their low byte, so look like one operation on registers or words 0 to 15
  (a guess).

## Not known

The encoding of any instruction beyond the above, registers, flags,
delay slots (a `BF6A0000` often has a word after it), how a function
takes its arguments from the input FIFO and puts replies in the output
FIFO, the clock, what `00` and `01` words (data? short immediates?) are,
and everything about how the programs of different games differ. The 2C
chip's (MB86235) instruction format (`mb86235.md`) is 64 bits and unrelated
as far as anything shows.

## Tools

- `make tgp-disasm GAME=srallyc`: splits an image (default
  `out/GAME/tgp.bin`) into header, dispatch table and function entry
  points, counts opcode bytes, and lists the words with the slot or
  header they belong to. Nothing decoded.
- `make run GAME=srallyc`: the `tgp calls` table and `tgp-calls.txt`.
