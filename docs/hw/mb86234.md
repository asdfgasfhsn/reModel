# MB86234 (the Model 2A TGP): what is known of its programs

The Model 2A's geometry processor is a Fujitsu MB86234 (the "TGP" of the
original Model 2 and 2A boards; the 2C's is an MB86235, `mb86235.md`). No
public manual for it has been found, and nothing here is taken from any
emulator: it is read from the one program image there is (`srallyc`'s) and
from the calls the game makes to it. **The instruction set is only partly
known** and the program is *not run* by reModel: the model in
`model2::tgp2a_hle` does what each function was read to do instead
(`model2a.md` §6). Every statement below says how it is known:

- **confirmed**: the program's own code demonstrates it (a value it
  computes, a loop count that matches a call's word count, two
  independent places that agree);
- **hypothesis**: fits everything seen, nothing contradicts it, nothing
  proves it;
- **unknown**.

Source: the 1,665-word program `srallyc` uploads (`out/srallyc/tgp.bin`,
written by `make run GAME=srallyc`; it is also in the game's program ROM
at `0x5AE94`), and the calls the game makes (`model2a.md` §4). The game's
own test menu has no coprocessor test with expected answers: its
"Self Check Status Report" prints counters (the program size, `COPRO
PROGRAM SIZE x681 Words`, is the image's 1,665; the command counts of
function 4; per-function error counts, "Coprocessor Function Errors").

## Program layout

- **Fixed 32-bit words** (*confirmed*): uploaded one store per word.
- **Header: six jump words** (*confirmed* as words of this form, *hypothesis*
  that they are vectors): `BF600010 BF600006 BF600006 BF600006 BF60000A
  BF600006`. Word 0 (reset) goes to `0x10`, the others to `0x6` and `0xA`,
  short routines that end in `BF6E0000` (a return from interrupt:
  *hypothesis*). The same six words begin the programs of `daytona`,
  `vcop`, `desert`, `manxtt`, `motoraid`, `dynamcop` and `vf2`.
- **Start-up (`0x10`-`0x6B`)** (*confirmed* by reading it): stores
  constants in a block of cells `0..0xF` (0, 1, -1, 0, 1.0, -1.0, 1/pi,
  the matrix stack's base `0x130`, ..., see below) and builds two tables of
  series coefficients at `0x220` and `0x23A` (the coefficients of a
  sine/cosine polynomial: 1/2, 1/24, 1/720, ... are what the stores
  hold, so the TGP computes sines by polynomial, not from a table).
- **Main loop (`0x70`-`0x97`)**: the loop at `0x70`-`0x75` writes the
  constant in cell `0xB` (8) to the output FIFO once a word has been
  read, which is how the load check gets its 8 (*hypothesis*: it is the
  only place the constant is written out). Then each iteration reads a
  command word,
  checks that its three copies of the function number agree (the
  `F << 23 | F << 8 | F` form; a failure goes to the error logger at
  `0xA1`, which writes to external memory at `0x7FFE`), loads `0xAF`,
  adds the number and **calls the word at that address** (`BF66 4019`:
  a call through the accumulator, *hypothesis* for the encoding, but the
  `3B0000AF` and the add are in the code), then adds 1 to the cell at
  `0x65` (the command counter) and loops.
- **Dispatch table at words `0xAF`-`0x12E`: 128 entries, function number
  F = word `0xAF + F`** (*confirmed* by the `0xAF` base in the loop above).
  The word before it (`0xAE`) and after it (`0x12F`) are returns
  (`BF6A0000`); 48 of the slots (unused function numbers) point at the
  return at `0x12F`; the other 80 reach 81 distinct entry points. (The
  first milestone's notes read the table as 130 entries from `0xAE`: one
  slot off. All its function-to-code mappings shift by one: function 0x22
  is at `0x27E`, not `0x26F`.)
- **Functions are short** (*confirmed*): most end at their first return
  (function 2 is one move and a return); a few call shared routines (the
  sine at `0x1AB`, `0x1E6` and `0x1E8`, the square root).
- **`BF6A0000` is a return** (*confirmed*: every function ends with one
  and the main loop's call comes back to the counter update);
  `BF60xxxx` a jump, `BF64xxxx` a call (*confirmed* by the call to the
  sine routine at `0x1E6` and its return), `BF66 4019` a call through the
  accumulator, `BF6E0000` a return from interrupt (*hypothesis*).
  `BExxxxxx` is a conditional jump to the 16-bit address, with a
  condition byte in bits 16-23: `0x10` jumps when the last result was not
  negative, `0x20` when it was zero (*confirmed* by the matrix stack's
  depth checks, below); `0x00`, `0x2C` and `0xA0` also occur and are
  *unknown*.

## Instruction words

The top byte is not one opcode: it is a format. Seen, with the evidence:

| Top byte | Form | How known |
|---|---|---|
| `1C`-`1F` (the 55%) | a **move** and an **ALU operation** in parallel | see below |
| `00`-`03` | a multiply (and accumulate) with an operand and a memory cell | *hypothesis*: the chains of them are dot products (`model2a.md`) |
| `3B` imm24 | load the accumulator with a sign-extended integer | *confirmed*: `3BFFFFFF` is -1 where the program needs -1; `3B000130` is the stack base |
| `5A` e / `5B` m | build a float in the accumulator: `5A` sets the exponent from the low byte (mantissa 0), `5B` sets the 23-bit mantissa and, in bit 23, the sign | *confirmed*: `5A00007F`+`5B490FDB` is pi/2, `5A000080`+`5B490FDB` pi, `5A00007D`+`5B22F983` 1/pi, `5A00007F`+`5B800000` -1.0 |
| `39` imm24 | accumulator minus a 24-bit immediate | *hypothesis* from `3900000C` (the pop's -12) |
| `40`-`43` imm24 | set address register 0-3 | *confirmed*: `41000200`, `43000220` then stores that fill a table from `0x220` up |
| `3C nn iiii` | `3C04 cccc`: repeat the next instruction *cccc* times (*confirmed*: 12 repeats for the 12-word matrix moves); other `nn` set unknown control registers | |
| `63400000` / `63000000` | bracket accesses to external memory | *hypothesis* |
| `36`, `3D`, `50`-`52`, `54`, `59`, `5F` | immediate forms of other ALU operations | *unknown*: `51 00007F` and `5A 00007F` have the exponent of 1.0 |
| `7C`, `FE` | `FE` is a loop jump back to its own block in the load-check loop | *unknown* |

### The move+ALU word (`1C`-`1F`)

Fields, high to low: `op:8` (`1C`-`1F`), `byte1:8`, `B:8`, `C:8`.

- **ALU function** = `(op & 3) << 3 | byte1 >> 5`, 5 bits, 0 for none.
- `byte1 & 3` = `k`, `(byte1 >> 2) & 7` = `m`. `m = 7` is a plain
  register/memory move; `m < 7` forms are **block moves** (below) and
  bank-to-bank copies (*hypothesis*).
- `B = U:1 | X:6 | I:1`, `C:8`.
- Plain move: `k = 0` stores register `X` to cell `C`; `k = 3` loads `X`
  from cell `C`; for `k = 1, 2` the direction follows `U` (1 loads).
  (*Confirmed*: the pair `1C1C 3207` / `1C1D B207` stores and loads cell 7;
  `1C1C 4265` stores the next input word to cell `0x65` and `1C1D C465` puts
  it on the output.) Cell `C` is `C & 0x3F` with `0x40` set in cases that
  look like a bank flag (*unknown*: `1C1C4253` writes the input register
  the multiplier reads as `0x13`).
- **Special cells** (*confirmed*): `0x21` is the input FIFO (reading it
  takes the next word the host wrote), `0x22` the output FIFO (writing
  it gives the host a word), `0x19` the accumulator (loaded by `3B`, `5A`,
  `5B`), registers `2` and `3` of the `X` field are the address registers
  (`1C1D 8607` loads address register 3 from cell 7, the matrix pointer).
- **Indirect cell** (`C >= 0x80`, `I = 1`): through address register 3;
  `C & 7` is the step added afterwards (`0xA1` and `0x81`: +1, `0xA4`: +4;
  *confirmed* by the 12 consecutive words of a matrix and the three
  every-fourth words of the vector registers).
- **Block move** (`m < 7`, `I = 1`): `rep` times, `[AR3]` += `[AR2]` (copy)
  with the step in `X`: `X = 0x21` steps 1 and `X = 0x24` steps 4 (the
  identity function writes 12 zeros, step 1, then 1.0 three times, step
  4). *Confirmed* in the cases read (matrix push, pop, identity).
- **ALU operations**: operands and results are fixed registers: the
  accumulator `0x19` and register `0x10` in, the result in `0x19`;
  multiplication `R10 * R13` into `0x1C`. The operands are those of
  the *previous* word's moves (they are read before the move of the word
  that names the operation). Of the 5-bit codes:
  - 26 integer add, 27 integer subtract/compare, setting the flags the
    `BE` conditions read (*confirmed*: the matrix stack's depth logic);
  - 8 a float multiply, `R10 * R13` into `0x1C` (*confirmed* by the
    vector normalise, which multiplies each component by the inverse
    length with it three times and outputs `0x1C` each time);
  - 6 and 7 float add and subtract of the accumulator and register `0x10`
    (*hypothesis*: functions 8 and 9, the two adjacent two-word-in,
    one-word-out library functions, differ in this code only);
  - 9, 12, 10, 13, 17, 20: used in the inverse-square-root, square-root and
    sine routines (*unknown* individually);
  - the others (1, 2, 5, 11, 14-16, 22-24) *unknown*.
- An ALU-only word is `xxxx 1E10` (move of cell `0x10` to register `0xF`,
  a no-op): *hypothesis*.

### Memory

*Confirmed* by reading how the functions use their cells (the cells are
the accumulator's neighbours and the host-visible state):

| Cells | Use |
|---|---|
| `0..0xF` | constants and the matrix stack variables: `[7]` the current matrix's address, `[8]` the stack base `0x130`, `[9]` the depth, `[0xA]` the depth limit 7, `[0xB]`-`[0xF]` 8, 256, 512, 64, 63 |
| `0x10`..`0x1B` | working registers (`0x10` the ALU's second operand, `0x13`-`0x15` the multiplier's inputs, `0x19` the accumulator, `0x1C` the product) and, as the destination of matrix loads, 12 words |
| `0x28`..`0x33` | the 12 results of the matrix concatenation (function `0x24`) |
| `0x34`..`0x3F` | temporaries (sine/cosine in `0x34` and `0x36`) |
| `0x65` | the command counter (`0x03` writes it, `0x04` reads it) |
| `0x70`.. | the four vector registers, as arrays: x at `0x70 + i`, y at `0x74 + i`, z at `0x78 + i` |
| `0x7C` | the unknown-function error count (`0x02` reads it) |
| `0x130`.. | the matrix stack, 12 words (a 3x3 rotation row by row, then the translation) per slot, 8 slots |
| `0x220`, `0x23A` | the series coefficients |

## The functions (found by reading the code)

`model2a.md` §6 has the table with what each does and how sure that is.
The ones the game uses are the matrix stack (push, pop, set, read, reset,
identity), translate, scale, rotate about each axis, transform a point,
normalise, the four vector registers, two six-word functions that return
one number, the error and command counters, and several (`5`, `0x32`-`0x34`,
`0x48`, `0x54`, `0x5D`-`0x5F`) that take words and give nothing back to the
host: they output to the geometrizer, which is not modelled.

The library behind the numbers `8`-`0x17` (two-input and one-input
float functions, never called by this game) is in the program too.

## Not known

The encoding of the multiply group `00`-`03` (which matrix element each
operand names), the ALU function codes beyond those above, the
`m < 7` bank-copy forms other than those read, the condition codes of `BE`
beyond two, the immediate forms `36`, `3D`, `50`-`52`, `54`, `59`, `5F`,
how the lookup ROMs (`opr-14742a.45/.46`, `.58/.59`, `.62/.63`, listed as
`CoproData`; sine, reciprocal and inverse square root) are addressed by
the program, delay slots (none were needed to read any function), the
clock, the instruction cycle count, and the rounding and special-value
behaviour of the float unit. The 2C chip's (MB86235) format
(`mb86235.md`) is 64 bits and unrelated as far as anything shows.

*Why the chip is not run yet:* running the program needs every one of
those: a function is correct only if the multiply group's operand
selection and each ALU code it uses are. The way forward is the one the
functions above were found by: take the shortest functions with known
mathematics (the sine routine at `0x1E6`, the normalise at `0x30E`, the
distance at `0x51C`), execute them with a candidate meaning, and keep a
meaning only if the result is the mathematics.

## Tools

- `make tgp-disasm GAME=srallyc`: splits an image (default
  `out/GAME/tgp.bin`) into header, dispatch table (slot = function
  number) and function entry points, counts opcode bytes, and lists the
  words with the function they start. Nothing decoded.
- `make run GAME=srallyc`: the `tgp calls` table and `tgp-calls.txt`.
